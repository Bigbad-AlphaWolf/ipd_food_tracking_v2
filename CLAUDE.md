## Project Overview

Food Tracker is an Angular 20 application for employee meal voting and admin meal operations, using standalone components, PrimeNG, PrimeFlex, and Supabase (Auth + PostgreSQL with Row Level Security).

## Commands

Always use the npm scripts, not direct `ng` commands — they run environment sync (`scripts/sync-env.mjs`) first, which generates `src/environments/environment.ts` and `environment.prod.ts` from `.env` files.

```bash
npm start                                          # sync dev env + ng serve
npm run build                                      # sync prod env + ng build
npm test                                           # sync dev env + ng test
npm test -- --watch=false --browsers=ChromeHeadless  # single CI-style run, used to validate changes
npm run watch                                       # sync dev env + ng build --watch (development config)
npm run sync-env / npm run sync-env:production      # regenerate environment files only
```

To run a single spec file, use Angular's `--include` flag, e.g.:
```bash
npm test -- --watch=false --browsers=ChromeHeadless --include='**/auth.service.spec.ts'
```

If environment-related failures occur, verify `SUPABASE_URL` and `SUPABASE_ANON_KEY` in `.env` (copy from `.env.example`).

## Architecture

### Environment sync (do not hand-edit environment files)

`src/environments/environment.ts` and `environment.prod.ts` are generated by `scripts/sync-env.mjs` from `.env` / `.env.local` / `.env.development(.local)` / `.env.production(.local)`. Never edit them directly — edit the `.env` files and rerun the relevant npm script.

### Routing and auth flow

- `app.routes.ts` is the root route table: `/login` and `/register-employee` are public/guarded standalone routes; everything else is nested under a root path guarded by `authGuard` and rendered inside `AppShellComponent` (`layout/app-shell.component.ts`).
- The empty child route uses `roleRedirectGuard` to send authenticated users to `/admin/dashboard` or `/employee/dashboard` based on role.
- `/admin/**` and `/employee/**` are lazy-loaded route trees (`admin/admin.routes.ts`, `employee/employee.routes.ts`) protected by `roleGuard('admin')` / `roleGuard('employee', 'admin')` (`core/guards/role.guard.ts`).
- `AuthService` (`core/services/auth.service.ts`) is the single source of truth for session/profile state, exposed as signals (`session`, `profile`, `isAuthenticated`, `roles`, `role`). Guards and components call `authService.ready()` to await initial session bootstrap before checking auth state. Use its `hasRole` / `hasAnyRole` helpers instead of comparing role strings directly.
- Login accepts either an email or a phone number; non-email identifiers are resolved to an email via the `resolve_auth_identifier` Supabase RPC before calling `signInWithPassword`.

### Role model

Roles support multi-role users via `profiles.roles` (array) with legacy single-role compatibility via `profiles.role`. `AuthService.resolveRoles()` merges both, dedupes, and defaults to `['employee']` if empty — keep this compatibility in mind when touching role/profile logic (see `supabase/migrations/20260620_000002_profiles_roles_array.sql`).

### Feature module layout

- `core/`: singleton services (`AuthService`, `SupabaseService`, `LoadingService`, `ToastService`, `LanguageService`, `GlobalErrorHandlerService`), guards, and shared models (`core/models/app.models.ts` — keep public API/domain types in sync with this file).
- `auth/`: login and employee self-registration pages.
- `admin/`: admin-only pages (dashboard, meals CRUD, surveys CRUD, user role management, monthly reports) and `admin.service.ts`.
- `employee/`: employee pages (dashboard, today's survey, monthly history, profile) and `employee.service.ts` / `employee.util.ts`.
- `layout/`: app shell and navigation.
- `shared/components/`: reusable building blocks (`app-table`, `confirm-delete`, `empty-state`, `page-header`, `search-toolbar`, `language-switcher`, `loading-spinner`, `route-placeholder`).

Keep all Supabase access inside services (`admin.service.ts`, `employee.service.ts`, `auth.service.ts`, `supabase.service.ts`), not directly in components.

### Supabase backend

Schema and RLS policies live in `supabase/migrations/` (apply via the Supabase SQL editor — there is no local Supabase CLI workflow configured). Key RPCs called from the app:
- `resolve_auth_identifier(input_identifier)` — maps a phone number to an email for login.
- `get_admin_dashboard_metrics()` — KPI/trend data for the admin dashboard.
- `get_monthly_report(report_month, report_year, employee_search)` — export-ready report rows.
- `is_admin()` — used inside RLS policies.

A trigger (`handle_new_user`) provisions a matching `profiles` row when an Auth user is created. When changing role or profile behavior, check both migration files and preserve backward compatibility with the legacy `role` column.

## Angular Conventions

- Standalone components only — do not add NgModules, and do not set `standalone: true` in decorators (it's the default).
- Use `ChangeDetectionStrategy.OnPush` and `inject()` over constructor injection.
- Use signals and `computed` for local state; use `set`/`update`, never a signal's `mutate`.
- Use native control flow (`@if`, `@for`, `@switch`), and prefer `input()`/`output()` functions over decorators.
- Prefer class/style bindings over `ngClass`/`ngStyle`.
- For new components, split into `component.ts` / `component.html` / `component.css` or `.scss` files rather than large inline templates (existing simpler components use inline templates — follow the pattern of the file you're editing).
- Reactive forms with `FormBuilder` nonNullable groups; keep forms typed with explicit validation.
- Use PrimeNG components and PrimeFlex utility classes consistently.
- Change detection is zoneless (`provideZonelessChangeDetection` in `app.config.ts`).

## i18n

Translations are loaded via `@ngx-translate` from `public/i18n/*.json` (`provideTranslateHttpLoader`, prefix `/i18n/`), with `LanguageService` bootstrapped eagerly via `provideEnvironmentInitializer`. Default/fallback language is `en`.
